zMapUnlocker — HANDOFF / рабочая шпаргалка
Обновлено: 2026-11-19

ЦЕЛЬ
Для Gothic II Addon: при открытой интерфейсной карте разрешить горизонтальное вращение мышью и перемещение ГГ. Проверить, обновляется ли GPS-маячок (позиция и направление взгляда) в реальном времени. Если нет — найти механизм его обновления и вызвать его безопасно.

РАБОЧИЕ ОГРАНИЧЕНИЯ
- Рабочая ветка: feature/zMapUnlocker-map-live-marker.
- Рабочий исходник: только Plugin_G2A.cpp.
- Пользователь собирает только workflow .github/workflows/buildG2A.yml.
- Не менять другие файлы проекта ради реализации; handoff хранится в Temp/main.
- Не сливать feature-ветку в main без прямой просьбы.
- Самостоятельно выбирать объём одного набора изменений, коммитить и давать конкретный тест.
- Не повторять стандартные инструкции сборки.

ИСТОРИЯ ЭКСПЕРИМЕНТОВ
1. Ранняя реализация с несколькими хуками и опросом ввода вылетала при открытии карты; Crash.txt содержал CALLSTACK 0023:0135F470 <UNKNOWN>.
2. Коммит ed38910456786568b3442283acf742ef02c70f43 отключил экспериментальные хуки и обращения к UI.
3. Коммит f5502c4c9c2b1036a5872c1d590ea0ab18626f1d включил только перехват oCViewDocumentMap::UpdatePosition (G2A 0x0068D7B0). Пользователь подтвердил: игра не вылетала, карту открыл/закрыл, лог содержал только [plugin] Game_Entry — строк UpdatePosition не было.
4. Коммит b5b926f7fb7c791e41f2c8d171009afacdbb8cc9 добавил перехват oCDocumentManager::Show(int) (G2A 0x0065F300), сохранив UpdatePosition.
5. После сборки этой версии пользователь сообщил о вылете при открытии карты. Новый crash report в сообщении: CALLSTACK 0023:0135F474 (четыре нулевых аргумента) <UNKNOWN>. В Temp/Crash.txt на GitHub на момент проверки оставался старый отчёт с адресом 0135F470, то есть новый отчёт ещё не был загружен туда.
6. Сравнение двух последних тестов: только UpdatePosition — без вылета; UpdatePosition + Show — вылет. Это сильное основание считать Show-перехват подозреваемым, но callstack сам по себе не доказывает точную причину.

ТЕКУЩЕЕ СОСТОЯНИЕ
- Ветка: feature/zMapUnlocker-map-live-marker.
- Последний коммит Plugin_G2A.cpp: 523b8511e6b27500861f4bf6610775b648db5bc1.
- Изменён только Plugin_G2A.cpp.
- Перехват DocumentManager::Show удалён.
- Оставлен только UpdatePosition с логированием ENTER/RETURN. В Game_Entry логируются THookInfo (lpOriginal, lpPointer, lpDetour, ulProtected), а также CCallBack::IsHooked и IsExist.
- Game_Loop, Game_MenuLoop и остальные callbacks пустые; ввод и UI не затрагиваются.
- Лог: zMapUnlocker.log в рабочей директории игры.

СЛЕДУЮЩИЙ ТЕСТ
1. Собрать DLL из текущей feature-ветки.
2. Запустить игру, открыть карту, подержать несколько секунд, закрыть Escape.
3. Сообщить, вылетает ли игра. Для этого теста достаточно прислать содержимое zMapUnlocker.log прямо в чат; в Temp/main пока ничего не загружать, если лог пустой/не изменился.
4. Если будет вылет — положить свежий crash report туда же.

ИНТЕРПРЕТАЦИЯ
- Последний тест: без вылета, лог содержит три строки [plugin] Game_Entry из трёх сессий (файл работает в append-режиме); строк UpdatePosition нет. Поэтому добавлена диагностика THookInfo в Game_Entry. Пользователь сообщил: original=0068D7B0, pointer=36590798, detour=71D911D0, protected=0. Pointer отличается от исходного, но это само по себе не доказывает успешную регистрацию. Следующая диагностика дополнительно вызывает CCallBack::IsHooked и IsExist для THookInfo. Лог должен показать оба результата; если IsHooked=1, установка зарегистрирована, и дальше будем выяснять, почему выполнение не попадает в detour. Если 0 — исследовать регистрацию/установку.
- UpdatePosition ENTER/RETURN: перехват работает.
- ENTER без RETURN: локализовать сбой внутри оригинального UpdatePosition/его вызова.
- Повторный вылет после удаления Show: гипотеза о Show как причине не подтверждается, потребуется изолировать установку UpdatePosition.
- Не возвращать Show в следующем тесте и не добавлять сразу несколько хуков. Не делать вывод, что UpdatePosition не вызывается: пока неизвестно, установился ли хук.

ДАЛЬНЕЙШИЕ ЭТАПЫ
После подтверждения стабильности исследовать жизненный цикл карты и ввод по одному методу за итерацию. Не снимать блокировки, пока не установлено, какой уровень блокирует управление. Затем проверить обновление GPS-маячка в движении и повороте. Удалить диагностику после завершения.
